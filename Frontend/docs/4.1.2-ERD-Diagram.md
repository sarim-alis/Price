## Relationships Summary

### **Core User & Product Relationships**

1. **USER → CUSTOMER** (1:1 for customer type users)
   - One user can be a customer

2. **USER → SELLER** (1:1 for seller type users)
   - One user can be a seller

3. **SELLER → PRODUCT** (1:*)
   - One seller can list many mobile products
   - Each product belongs to one seller

4. **CUSTOMER → ORDER** (1:*)
   - One customer can place many orders
   - Each order belongs to one customer

5. **SELLER → ORDER** (1:*)
   - One seller can receive many orders
   - Each order is fulfilled by one seller

### **Order & Transaction Relationships**

6. **ORDER → ORDER_ITEM** (1:*)
   - One order can contain many order items
   - Each order item belongs to one order

7. **PRODUCT → ORDER_ITEM** (1:*)
   - One product can be in many order items
   - Each order item references one product

8. **ORDER → PAYMENT** (1:1)
   - One order has one payment
   - Each payment is for one order

9. **PAYMENT → TRANSACTION_LOG** (1:*)
   - One payment can have multiple transaction logs
   - Each transaction log belongs to one payment

### **Review & AI Relationships**

10. **PRODUCT → REVIEW** (1:*)
    - One product can have many reviews
    - Each review is for one product

11. **CUSTOMER → REVIEW** (1:*)
    - One customer can write many reviews
    - Each review is written by one customer

12. **PRODUCT → REVIEW_SUMMARY** (1:1)
    - One product has one AI-generated review summary
    - Each summary is for one product

13. **CUSTOMER → AI_RECOMMENDATION** (1:*)
    - One customer can receive many AI recommendations
    - Each recommendation is for one customer

14. **PRODUCT → AI_RECOMMENDATION** (1:*)
    - One product can be recommended multiple times
    - Each recommendation is for one product

### **Support & External Relationships**

15. **SELLER → FRAUD_DETECTION** (1:*)
    - One seller can have multiple fraud checks
    - Each fraud check is for one seller

16. **CUSTOMER → CHATBOT_LOG** (1:*)
    - One customer can have many chatbot interactions
    - Each chatbot log belongs to one customer

17. **PRODUCT → EXTERNAL_DATA** (1:*)
    - One product can have multiple external data entries
    - Each external data entry is for one product

18. **CUSTOMER → PREDICTION** (1:*)
    - One customer can request many price predictions
    - Each prediction can be linked to a customer (optional)

## Entity Descriptions

### **Core Entities**

1. **USER**: Base entity for all system users (customers and sellers)
   - Handles authentication and basic profile information

2. **CUSTOMER**: Extended user entity for buyers
   - Stores preferences, wishlist, loyalty points

3. **SELLER**: Extended user entity for mobile vendors
   - Business information, verification status, ratings

4. **PRODUCT (Mobile)**: Mobile phones listed for sale in the marketplace
   - Complete mobile specifications (brand, model, RAM, storage, cameras, battery, processor)
   - Price, stock, AI scoring for quality/value
   - Indexed by brand and price for fast queries

5. **ORDER**: Purchase transactions initiated by customers
   - Order details, status, shipping information

6. **ORDER_ITEM**: Individual mobile products within an order
   - Links orders to products with quantity and pricing

### **Transaction Entities**

7. **PAYMENT**: Payment information for orders
   - Payment gateway integration, transaction tracking

8. **TRANSACTION_LOG**: Detailed logs of all financial transactions
   - Audit trail with fraud detection scores

### **Review & AI Entities**

9. **REVIEW**: Customer reviews for mobile products
   - Ratings, text reviews with AI sentiment analysis

10. **REVIEW_SUMMARY**: AI-generated summaries of product reviews
    - Aggregated ratings and sentiment breakdown

11. **AI_RECOMMENDATION**: AI-generated mobile product recommendations
    - Personalized recommendations based on customer preferences and behavior

12. **PREDICTION**: AI-powered price predictions for mobile specifications
    - Customers can input specs to get estimated market price
    - Separate from actual products for sale

### **Support Entities**

13. **FRAUD_DETECTION**: Seller verification and fraud checks
    - AI-powered fraud scoring for seller legitimacy

14. **CHATBOT_LOG**: NLP chatbot interaction logs
    - Customer queries and AI responses with intent classification

15. **EXTERNAL_DATA**: External data integration for products
    - Market data, competitor pricing, specifications validation

## Database Design Notes

- **User Type Inheritance**: USER entity uses single-table inheritance with `user_type` discriminator
- **Product Focus**: PRODUCT entity specifically designed for mobile phones with detailed specifications
- **AI Integration**: Multiple AI touchpoints - price prediction, recommendations, review analysis, fraud detection, chatbot
- **Audit Trails**: `created_at` and `updated_at` timestamps on major entities
- **Performance**: Strategic indexes on brand, price, and createdAt for fast queries
- **Scalability**: CUID-based primary keys for distributed systems
- **External Integration**: EXTERNAL_DATA entity allows enrichment from third-party sources
- **Fraud Prevention**: FRAUD_DETECTION entity ensures seller legitimacy
- **Customer Support**: CHATBOT_LOG entity tracks all NLP-powered customer interactions
