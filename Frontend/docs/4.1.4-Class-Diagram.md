## Key Design Patterns

### **1. Inheritance Pattern**
- **User** is an abstract base class
- **Customer**, **Seller**, and **Admin** inherit from User
- Demonstrates polymorphism and code reuse

### **2. Service Layer Pattern**
- Service classes encapsulate business logic
- Separate concerns from data models
- Examples: UserService, ProductService, OrderService

### **3. Association Pattern**
- **Composition**: Order contains OrderItems (strong ownership)
- **Aggregation**: Product referenced by OrderItem (weak relationship)

### **4. Facade Pattern**
- Service classes provide simplified interfaces to complex subsystems
- AIService abstracts AI model complexity

## Attributes & Methods Naming Conventions

### **Attributes**
- **Private attributes**: Prefixed with `-`
- **Public attributes**: Prefixed with `+`
- **Naming**: camelCase (e.g., `userId`, `orderStatus`)
- **Types**: Explicitly defined (String, Integer, Float, DateTime, Boolean)

### **Methods**
- **Public methods**: Prefixed with `+`
- **Naming**: camelCase with verb prefix (e.g., `create()`, `update()`, `get()`)
- **Return types**: Explicitly shown (e.g., `: Boolean`, `: Array`, `: String`)

### **Method Categories**
1. **CRUD Operations**: `create()`, `update()`, `delete()`, `get()`
2. **Business Logic**: `predictPrice()`, `analyzeSentiment()`, `detectFraud()`
3. **Validation**: `verify()`, `validate()`, `check()`
4. **Computation**: `calculate()`, `generate()`, `process()`

## Class Responsibilities

### **Entity Classes (Data Models)**
- Represent domain objects
- Contain business data (attributes)
- Include basic CRUD methods
- Examples: User, Product, Order, Review

### **Service Classes (Business Logic)**
- Implement complex business logic
- Coordinate multiple entities
- Handle external integrations
- Examples: UserService, AIService, PaymentService

### **Enumeration Classes**
- Define valid values for specific fields
- Ensure type safety
- Examples: UserType, OrderStatus, PaymentMethod
